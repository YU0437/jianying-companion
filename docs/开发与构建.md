## 环境准备

```bat
python -m venv C:\path\to\envs\tk
C:\path\to\envs\tk\Scripts\pip install -r requirements.txt
:: 只想跑起来、不打安装包的话，最小组合是：pip install pillow
```

| 需要的 | 说明 |
|---|---|
| Python **3.10+**（开发用 3.13） | 需要 `tkinter`（Windows 官方安装包默认自带） |
| `pillow` | **唯一的必需运行时依赖**（抓屏、像素比对） |
| `pywinauto` | **可选但建议**：被别的窗口全遮住时点任务栏按钮的兜底通道。源码里 `import` 在 `try` 里，装不上也能跑 |
| `pyinstaller` | 只在打包时需要 |
| `pyflakes` | 只在静态检查时需要 |
| Inno Setup 6 | 只在做安装包时需要（[官网下载](https://jrsoftware.org/isdl.php)） |

> ★ 虚拟环境建议**带 tkinter**（比如用官方 python.org 装出来的解释器建 venv），
> 否则 GUI 相关的测试跑不起来。

## 代码结构速览

| 文件 | 职责 |
|---|---|
| `jy_core.py` | **内核**。窗口枚举、按键注入、像素自检、备份/还原、整条流水线。没有任何 GUI 代码，可以单独跑和测 |
| `剪映伴侣.py` | **GUI**。一个 tk 悬浮球 + 右键菜单 + 队列驱动的事件循环。可以 `SetParent` 嵌进剪映窗口 |
| `使用说明.txt` | 随安装包发货的面向用户的说明（**改行为记得同步它**） |
| `JianyingCompanion.spec` | PyInstaller 配置（onefile、关 UPX、带版本信息、带图标） |
| `剪映伴侣安装包.iss` | Inno Setup 脚本 |

设计上有一条硬规矩：**GUI 不做业务**。所有"会不会成功"的判断都在 `jy_core` 里，
GUI 只负责把 `status_cb / finished_cb` 投进队列、渲染成球上的字。

## 测试

```bat
python test_guard.py            # 主力回归（红线 + 文案 + 形状 + 行为）
python test_gui_smoke.py        # GUI 冒烟（真起一次 tk 窗口）
python test_settle.py           # 文件落盘判定
python _test_backup_restore.py  # 离线：备份/还原 + 红线守卫
```

**四套都必须全绿再打包。** 各自的定位：

| 测试 | 怎么写的 | 什么时候会红 |
|---|---|---|
| `test_guard.py` | 三类断言混用：<br>① **形状**（函数/常量在不在、源码里有没有某句）<br>② **行为**（真调用纯函数或打桩跑一遍）<br>③ **文案**（关键提示必须真在源码里） | 改了函数名、删了文案、改了顺序 |
| `test_gui_smoke.py` | 真构造 `Companion()`，打桩掉所有对外部世界的调用 | GUI 改坏了、菜单下标跑偏、模态框没打桩 |
| `test_settle.py` | 用真文件测"落盘判定" | 落盘判据改坏（会同名回退成"只看大小"） |
| `_test_backup_restore.py` | 纯离线，`core.config_path` 指向临时目录 | 红线被破（比如开始动产物文件） |

> ⚠️ **两个测试文件的 `check()` 签名不一样**：
> - `test_guard.check(name, got, want)` —— 第二参是**实际值**，内部做等值比较
> - `test_gui_smoke.check(name, cond, extra)` —— 第二参是**布尔条件**
>
> 从 `test_guard` 复制断言到 `test_gui_smoke` 时极易写出 `check("x", rc, 0)`
> —— `rc=0` 是假值，**测试会假红**；反过来写 `check("x", rc)` 则**恒真（假绿）**。

## 完整发布流水线

**顺序不能变。** 尤其 5 必须在 6 之前。

```bat
:: 1) 编译
python -m py_compile jy_core.py 剪映伴侣.py

:: 2) 静态检查（只允许 jy_core 里那条 local variable 'e' 未使用的告警）
python -m pyflakes jy_core.py 剪映伴侣.py test_guard.py test_gui_smoke.py _verify_exe.py

:: 3) 四套测试
python test_guard.py && python test_gui_smoke.py && python test_settle.py && python _test_backup_restore.py

:: 4) 打包 exe
python -m PyInstaller JianyingCompanion.spec --noconfirm --distpath dist --workpath build

:: 5) 核验 exe（函数名 / 常量 / 文案 / 默认配置 真的在里面）
python _verify_exe.py

:: 6) 部署到本机 + 重启复核（md5 比对）
python 重启伴侣.py

:: 7) 同步随包文档
copy /Y 使用说明.txt "%LOCALAPPDATA%\JianyingCompanion\使用说明.txt"

:: 8) 出安装包（★ 必须在第 4 步之后）
"%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe" 剪映伴侣安装包.iss
```

### 9) 入库 + 发 Release（★ 本机有两道 TLS 坑，照抄）

```bat
:: 9a) 推代码 —— 必须关掉 schannel 的吊销检查，否则必失败：
::     CRYPT_E_NO_REVOCATION_CHECK（GitHub 证书链在本机查不了 CRL/OCSP）
git -c http.sslVerify=false push origin main

:: 9b) 发 Release + 附安装包（本机没有 gh，用仓库里的脚本走 REST）
python _release.py v1.6.0 installer/剪映伴侣-Setup-1.6.0.exe
```

> ⚠️ **别把 `http.sslVerify=false` 写进 config**（`git config http.sslVerify false`）：
> 那是全局关校验，而这里只需要**推这一下**不查吊销。用 `-c` 就是"只对这条命令生效"。
>
> ⚠️ **`_release.py` 里的网络层是 `curl --ssl-no-revoke`，不是 urllib**：
> 本机**两台 Python 连 github.com / api.github.com 一律**
> `[SSL: UNEXPECTED_EOF_WHILE_READING]`（连 baidu 是 200，所以不是断网），
> 而 curl 能拿 200 —— 换成 urllib/requests 会原地复现这个错，`--ssl-no-revoke`
> 也不能省（省了就 `CRYPT_E_NO_REVOCATION_CHECK`）。
> 脚本每次都是"改 Release 标题正文 + 覆盖同名附件"，可以反复跑，不会堆出重复 Release。

`_verify_exe.py` 做的事：直接读打出来的 exe，把 PyInstaller 的归档解开，
反序列化出主脚本和 `jy_core` 的 code object，然后断言：

- 这一批新增的**函数名**真的在
- 这一批新增的**文案常量**真的是**精确常量**（不是子串）
- 几个关键**默认配置值**是对的（防止"改了 `default_config()` 但 exe 里还是旧的"）
- 草稿阶段表**首尾相接**（进度条不会跳空）
- 红名单里的函数**一个都没有**

> ★ 这一步是必要的：`py_compile` 和单元测试都只能证明**源码**是对的，
> 证明不了**打进 exe 里的那份**是对的（打包配置漏了 hiddenimport、忘了重打，
> 都会得到一个"看起来部署成功、其实新代码一行没生效"的结果）。

## 界面预览图怎么重出（`docs/ui-preview.png`）

README 顶上那张图**必须是真机渲染**出来的，不能手工拼 —— 手工拼的图在界面
改完之后会继续挂着旧配色，那就成了"文档说谎"。本机脚本 `_probe_readme2.py`
（和发版脚本同待遇，不入库）渲染五个状态拼成一张：

待机球 / 干活中的球（进度弧+数字）/ 悬停展开的胶囊 / 出错态胶囊 / 头顶通知卡

### 唯一要点：**直接取 `_blit()` 收到的那张位图**

第二十四批把上屏换成 `UpdateLayeredWindow` 逐像素 alpha 之后，预览图就没有
任何理由再去抓屏了：

```python
c._blit = lambda img: FRAME.__setitem__("main", img)      # 主窗（球/胶囊）
gui.Popup.show = _capture                                 # 头顶卡片
```

逐像素 alpha 下，"用户看到的"和"我们送进去的"**是同一份像素数据**，所以这份
位图就是最忠实的来源：没有抓屏、没有色键、没有壁纸混入、没有羽化阈值，一个
像素都不用猜。脚本也因此从 ~230 行降到 ~120 行。

三个仍然必须遵守的前提：

1. **钉住缩放**：`c._dpi = c._scale_follow = c._scale = 1.0`，并把
   `_dpi_checked_at` 推到很远的将来。否则在 125% 屏上出的是 1.25 倍的图，
   而且换显屏还可能中途触发 `_sync_dpi` → 重建 → 尺寸在取图途中变。
2. **关掉周期定时器**：`_follow_fast` 每 33ms 按**真实光标位置**改 `_hover`，
   手工摆好的"悬停展开"态会在取图前一瞬被收回小球。把 `_follow` /
   `_follow_fast` / `_watch` / `_pump` 在实例上换成空函数，并等一会儿让已经
   排进 `after` 队列的那批原版回调跑完、把链条重注册成空函数。
3. **补间要手动落终态**：`_anim_stop()` + 直接写 `_cur` 再 `_redraw()`
   （脚本里没有事件循环，真时间几乎不流动，补间永远跑不完）。

> ★ 挂钩 `Popup.show` 时签名要**逐参对齐**（`(self, img, x, y, alpha=1.0, spec=None)`）：
> 入场动画是按位置参传 `alpha` 的，写成 `**kw` 会在第 5 个位置参上 `TypeError`。
> 淡入期间会回调多次 → 只留 `alpha` 最大的那一帧。

### 已废弃：色键抓图（旧 `_probe_readme.py`，留着当教训）

那一版是"把窗口色键换成品红 → `ImageGrab` 抓屏 → 按'离品红多远'反解覆盖度"。
在**色键透明**（`-transparentcolor`）时代那是唯一能用的办法，但它有两个硬伤：
① 屏幕上的像素已经被 DWM 和壁纸重新混合过，抓到的是"混合结果"；
② 边界只能靠阈值+羽化去猜 → 旧预览图上每个形状周围都挂着一圈**紫边**。
色键上屏一被换成 ULW，这条路连同它的坑就一起退役了。

> ★ 仍然成立的老教训：`attributes("-transparentcolor", "")` **不抛异常也不生效** ——
> 想"关掉色键"这条路走不通。**"没抛异常" ≠ "生效了"。**

## 踩过的坑（构建/打包相关）

这些都是**真踩过**的，不是理论：

### 1）★★★ 先 PyInstaller，后 ISCC

先打安装包、之后又重打 exe 的话，**安装包里嵌的还是旧 exe**。
E2E 装完测的是上一版，现象会非常诡异（新功能"没生效"，其实是根本没打进去）。
固定顺序：**源码 → 测试 → PyInstaller → _verify_exe → ISCC → 再 E2E**。

### 2）★★ Inno Setup 读结果文件只能用 `AnsiString`

`LoadStringFromFile(Path, S)` 的第二个参数**只能是 `AnsiString` 变量**，
传 `String` 是**编译期** `Type mismatch`。写法：

```pascal
var A: AnsiString; S: String;
begin
  LoadStringFromFile(ExpandConstant('{app}\_结果.txt'), A);
  S := A;
end;
```

它按 **ANSI** 解字节，所以那个文件要按**系统 ANSI**（中文 Windows = GBK）写；
稳妥做法是**文件头几行放纯 ASCII 标记**（`JIANYING=1` / `DRAFT=1`），
用 `Pos()` 判存在，中文正文另起一段只给人看。

### 3）★ Pascal 块注释 `{ }` 不嵌套

注释里写 `{app}` 会**提前闭合**注释 → `Syntax error`。
注释里永远别出现 `{` / `}` 常量。

### 4）★ 命令行子命令要排在"单实例守卫"之前

`--autosetup` 这类安装期子命令，如果排在 `ensure_single_instance()` 之后，
用户机器上旧版正在跑时会被守卫吞掉（直接退出、什么都不干）。
`__main__` 的顺序：**CLI 子命令 → selftest → 单实例守卫**。

### 5）★ `Path("C:") / "x"` 是**驱动器相对**路径

不是 `C:\x`，而是"当前在 C 盘的那个目录下"。要写 `Path(f"{drv}:/")`。

### 6）★ 跨行隐式拼接的文案，在字节码里是**合并后的一整条常量**

```python
msg = ("第一行\n"
       "第二行\n")          # 常量是 "第一行\n第二行\n"，不是你写的那两段
```

所以核验常量时要写**完整拼接结果**，或者退一步按**子串**查
（按子串查时要确认那句话**全源码只出现一次**，否则会被注释/docstring 假绿）。

### 7）★ 断言查源码时，注释里提到目标行会假红

用 `src.index("关键词")` 找位置时，如果注释里也写了这个关键词，
命中的可能是注释。必要时用 `rindex()` 或限定在某个代码块切片里比对。

**第二十四批又踩了一次**，值得记下具体形态：DPI 声明的位置断言写成
`_main_src.find(".Tk()")`，而那段"这一行必须在 `tk.Tk()` 之前跑"的**说明注释**
里也写着 `.Tk()` —— 于是"首次出现位置"被找注释上去，断言假红。
正解是找**真正的构造点** `self.root = tk.Tk()`（找不到再退回 `rfind(".Tk()")`）。

## 改动这套代码时的硬规矩

1. **红线不能碰**：产物文件（`Resources\combination\*.mp4`）**一个字节都不动**。
   唯一允许写的是草稿目录里的 `.json`。`test_guard` 和 `_test_backup_restore` 会拦你。
2. **改行为必带"会红的旧断言"**：先写一条断言证明旧行为是错的，再改代码让它变绿。
   否则你证明不了自己真的改了什么。
3. **不许静默失败**：任何"我做不到"都必须返回 `ok=False` 并往上抛，
   让界面能如实告诉用户。**假装成功**是这套代码里最严重的 bug。
4. **文案提到的入口，菜单里必须真有**，而且名字一致（有测试守着）。
5. **改 `default_config()` ≠ 改生效值**：老用户机器上的配置已经写死了，
   所以核验要看**三层**（exe 里的默认 / 已部署配置 / 最终生效值）。
6. **主线程绝不 `sleep` 等外部程序**：一卡，悬浮球就冻住，用户看到的是"点了没反应"。
   所有等待都丢给工作线程。
7. **自重复的 `after()` 循环**必须把重注册放在 `finally` 里，并且兜住**泛异常** ——
   否则一条畸形消息就能打死整条链，从此球不再更新状态。
